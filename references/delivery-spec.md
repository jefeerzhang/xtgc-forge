# 最终交付规格（v0.3.2）

> `SKILL.md` 只保留索引；**本文件是主报告的唯一详细规格**。修改交付形态时改这里。

## 1. 完成态定义

用户只打开工作目录中的：

```text
00_研究计划报告.md
```

即可理解并带走选题结论；**不得**要求用户拼读 Step1–5 才能看懂题目。

| 层级 | 路径 | 用户 |
|------|------|------|
| ★ 主交付 | `00_研究计划报告.md` | 必读 |
| 交付入口说明 | `00_交付说明.md` | 打开目录时先看 |
| 过程文件 | `Step*` / `review_*` / `topic_scores.json` | 默认不读 |

## 2. 正文六段（顺序固定 · 先亮题）

| # | 标题 | 最低有效字符* | 最低论述段落* | 只允许写什么 |
|---|------|----------------|---------------|--------------|
| 1 | 选的题是什么？ | 200 | 1 | 标题、RQ、对象、类型、边界 |
| 2 | 为什么选这个题？ | 600 | 3 | 矩阵结构事实、文献证据、决策链 |
| 3 | 选题的意义是什么？ | 300 | 2 | 现实/学术/可执行（勿再叙矩阵） |
| 4 | 假设是什么？ | 600 | 3 | 每条：主张+直觉+可证伪(+SESOI) |
| 5 | 为什么能写出这样的假设？ | 400 | 2 | gap/文献/决策映射；禁止复述 H 全文 |
| 6 | 后面应该怎么做？ | 300 | 2 | 规格、步骤、数据、风险、最小行动 |

\*由 `scripts/check_step.py --step 6` 强制。

### 段间信息增量（反注水）

- §2 ≠ §3：§2 讲证据结构，§3 讲做成题对谁有何用  
- §4 ≠ §5：§4 讲命题内容，§5 讲命题合法性（对应哪条 gap/文献）

### SESOI 诚实写法

- 若无领域效应量来源：写明「探索性门槛，正式预分析再定」  
- 禁止无来源的精确百分比装权威  

## 3. 文内整合附录（不可省略）

| 附录 | 内容 | 硬要求 |
|------|------|--------|
| A | 文献矩阵 | 完整表；数据行 ≥ 文献数且 ≥ 5 |
| B | 要点卡 | 每篇至少一段 |
| C | Gap | 已知区 + 本题主 gap + 对照；有证据来源；**必须含「Gap 判定方法」段(反黑箱)** |
| D | 候选与选定 | 3+2 + 用户点名 |
| E | 识别要点 | 推断性必填；IV 可选 |
| F | 元信息/闸门 | 推荐 |

**禁止**：主报告只写「详见 Step2b-literature-matrix.md」而无矩阵正文。

## 3.1 附录 C 的「Gap 判定方法」段(反黑箱,v0.3.5)

主报告必须向用户解释**gap 是怎么判出来的**,不能只给结论表。判定方法段至少包含:

1. **判定规则(Step 2c 的 5 类)**:已知区 / 矛盾区 / 空白区 / 方法局限区 / 理论外推区,一句各定义
2. **证据链要件**:每条 gap 必须有「哪些文献各做了什么 → 互相之间差什么 → 凭什么算 gap」,禁止无证据的「感觉有空白」
3. **重要性分级**:高(矛盾/空白)/ 中(方法局限)/ 低(已知区避免),一句话说明为什么本题主 gap 定级

**推荐写法**:先给规则表,再用本题 1 条真实 gap 走一遍完整推理链(如:两篇文献各自只检验单工具 → 组合状态从未被检验 → 空白区、高价值)。

**闸门**:`check_step.py --step 6` 强制附录 C 含「Gap 判定方法」小节,且正文含「证据链」或等价词。

## 3.2 附录 C 的「威胁文献清单」段(v0.3.7)

找 gap 的另一面是找「杀你的那篇」:主报告必须列出谁能威胁本题的新颖性。

1. **分级**:按威胁新颖性程度 — 致命(该文献已占本题主贡献)/ 高(增量被稀释)/ 中(视角撞车、需转组态/机制路径)
2. **每行四要素**:威胁来源(具体文献或「不在本批文献集内的 X 类研究」)→ 它做了什么 → 对本题的威胁 → **本题靠什么活下来**(差异化依据,如识别策略/机制路径/情境窗口)
3. **诚实声明**:不在本批文献内的威胁来源须标注「需复跑核实」,不得断言其已存在

**闸门**:`check_step.py --step 6` 强制正文含「威胁文献」或等价词。

## 3.3 可读性层:术语翻译 + 断句(反黑话,v0.3.8)

**问题**:Step1–5 是内部审计留痕,但主报告常把内部黑话(GAP-C1 / t_score / Checkpoint / SESOI)直接写进正文——读者(导师/期刊)看不懂,报告「生硬」的第一来源不是文风,是黑话泄漏。

**正文 = 开头到 `# 整合附录` 之前;附录是技术对照区,允许黑话。**

1. **术语翻译层(强制)**:正文出现内部术语时翻译成人话,禁止直接复用——

| 内部术语(禁在正文) | 正文该写 |
|---|---|
| GAP-C1 / GAP-B1 等编号 | 「文献矛盾/空白:……」(用中文描述那个 gap,编号只在附录 C 对照) |
| t_score=0.42 / 反坍缩 | 「选题差异化程度」/「差异化层」(不说机制名,只说结论) |
| evidence_leverage / negative_value / feasibility= | 「文献支撑度」/「被推翻也有价值」/「可行性」 |
| topic_scores | 「候选评分」 |
| Checkpoint #3 / 5 闸 | 「方向确认环节」/「确认流程」 |
| SESOI | 「最小效应量」 |
| （探索性） | 并入句子:「暂按探索性门槛,正式预分析再定」 |

2. **断句规则(强制)**:正文句子(以 。；为界)目标 ≤ 60 字,超 100 字 = 闸门 FAIL。长句拆成短句 + 加主语;超长段落拆成多段,每段一个意思。

3. **可选增强(不强制)**:若已安装 `academic-humanizer-zh`(MIT),Step 6 后可用它做最后文风润色(治套话/价值词饱和/排比)。**注意**:它锁定技术术语,治不了黑话——黑话必须靠上面的翻译层。两者是「先翻译、后润色」顺序,不可颠倒。

**闸门**:`check_step.py --step 6` 校验正文(非附录)黑名单词汇 = 0,且正文无 >100 字句子。

## 4. 过程文件角色

- 必须生成并通过 `check_step`（审计）  
- **不是**用户主交付  
- 与主报告附录内容应一致；以主报告为对外准绳，过程文件变更后须回写主报告  

## 5. 复跑契约

仅当**同时满足**才可跳过 AskUserQuestion：

1. 用户当次明确说「按上次选择 / 不要再问 / 复跑」——**原话必须引用进 `00_复跑决策记录.md` 和 `interaction-log.md`**
2. 存在 `00_复跑决策记录.md` **且含用户当次原话引用 + 决策时间**（主报告附录 F 决策表只是**历史记录，不是当次授权**；不得以「附录 F 有决策表」为由跳过询问）
3. 文献路径与收窄条件未变更；若变更 → 必须重开对应 Checkpoint

**复跑 ≠ 无留痕**：复跑模式下 5 闸不再重新暂停，但 `interaction-log.md` 仍须为 5 闸各留一条确认记录（状态标「已确认·复跑授权」，原话引用用户当次的「按上次选择」类原话），否则 `check_step --step 6` 仍 FAIL。

**空壳拦截**：`00_复跑决策记录.md` 只有模板/占位符（无当次原话、无时间）→ 不得视为复跑授权，`check_step --step 6` FAIL。

否则仍执行 5 闸硬暂停。

## 6. 文献规模分档（防爆表）

| 篇数 | 主报告策略 |
|------|------------|
| 5–8 | 矩阵全收；要点每篇一段 |
| 9–20 | 矩阵全收；要点可按主题簇合并但仍覆盖每篇 ID |
| 21–50 | 先聚类；矩阵可分表；正文只深写核心簇，附录列全 ID |

## 7. Agent 对用户说话

1. 先给主报告路径  
2. 一句说明「过程文件在同目录供审计」  
3. 禁止把「9 个文件已生成」当作完成宣告的中心句
