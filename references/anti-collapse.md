# 反坍缩机制(Anti-Mode-Collapse)方法论

> v0.3.4 引入。用于 Step 3a 候选主题生成,防止 AI「选题坍缩」——反复给出同质、安全、可预测的题目。
> 本文档是通用语言改写 + 中文社科实证化的实现说明;不复制任何上游条款原文。

## 1. 问题定义:什么叫「选题坍缩」

AI 选题坍缩 = 无论给什么文献和 gap,生成器都收敛到同一批「最安全、最可预测」的题目。经管实证场景的典型模态模板:

| 模态模板(T ≥ 0.80) | 问题 |
|---|---|
| 「X 对 Y 的影响——基于 A 股上市公司的实证」 | 范围过宽、无差异化,审稿人秒拒 |
| 「X 与 Y 的关系研究」 | 无方向、无机制 |
| 「数字化转型/ESG 背景下 X 对 Y 的影响」 | 只换了情境标签,骨架未变 |
| 「XX 研究现状与对策」 | 描述性,无理论贡献 |

坍缩的根因:生成器按「最像正确答案」的概率采样,安全题最像。**必须显式点名模态题,再主动向低典型性方向采样**,才可能出差异化选题。

## 3. 核心概念:T-Score(典型性评分)

**T-Score = 0-1 的题目典型性/可预测度**。越高越「谁都会这么想」,越低越差异化(也越冒险)。

| T 区间 | 层级 tier | 特征 | 经管实证示例(抽象) |
|---|---|---|---|
| ≥ 0.80 | modal(避免) | 直接因果/相关主效应,无细节 | 「X 对 Y 的影响」 |
| 0.55–0.80 | **safe 安全层** | 加情境/调节/聚焦子样本,可保底发表 | 限定某政策窗口/某类企业/加入调节变量 |
| 0.35–0.55 | **differentiated 差异化层** | 新中介路径、边界条件、机制异质、政策组合 | 组合工具交互、链式路径、符号随情境反转 |
| < 0.35 | **innovative 创新层** | 挑战主流假设、反向因果、非线性/悖论、命名新现象 | 「监督反而助推漂绿」类反转命题 |

**T-Score 与 6 维评分(topic_scores.json)是两回事**:
- 6 维(importance/feasibility/...)回答「这个题好不好」——与典型性无关,安全题也可能 importance 很高
- T-Score 回答「这个题是否太安全」——只负责防坍缩
- 二者同时保留:一个创新题 feasibility 低,照样进备选;一个安全题 total 高,也可能因坍缩被要求改写

## 4. 三阶段流程(Step 3a 内执行)

### Phase 1 · 模态识别(Modal Identification)

**在生成任何候选之前**,先显式列出 2-3 个「任何人看到这些 gap 都会提」的最安全题目,标 T ≥ 0.80,写清为什么避免:

```markdown
## 模态识别(反坍缩 Phase 1)
以下是从本批 gap 最可能「坍缩」出的题目,已主动避免:

| 模态题(示例) | T-Score | 避免理由 |
|---|---|---|
| 绿色信贷对企业漂绿的影响——基于 A 股上市公司 | 0.90 | 已知区主效应,无新信息 |
| 企业漂绿与融资成本的关系研究 | 0.85 | 无方向、无机制、无边界条件 |
| 环境税规制下企业漂绿的影响因素研究 | 0.82 | 描述性罗列,无因果识别 |

➡️ 以下候选均刻意偏离上述模态。
```

要点:**不点名,坍缩就不可见**。这一步让「我们避开了什么」可审计。

### Phase 2 · 分层替代(T-Score 梯度生成)

从 Step2c gap 中派生候选时,**按典型性梯度分配**,而不是按「谁最像答案」:

- **3 主推**:必须覆盖 **≥ 2 个不同层级**,且至少 1 个 T ≤ 0.50(即不能 3 个全在安全层)
- **2 备选**:层级自由(通常放 1 个安全层保底 + 1 个更远距离的冒险层)
- 每个候选标注 **T-Score(数值)+ 层级(tier)**

分层与 gap 的对应(推荐):
- 安全层 ← 方法局限区 gap(补一个调节/聚焦子样本)
- 差异化层 ← 矛盾区 gap(调和矛盾,找边界条件)/ 外推区 gap(换情境 + 新机制)
- 创新层 ← 空白区 gap 中最反直觉的 / 同质化文献的「外推 gap」

### Phase 3 · 反坍缩校验(Collapse Check)

`check_step.py --step 3a` 强制:

1. Step3a 文件含 **「模态识别」小节**(必须点名过模态题)
2. 每个候选含 **t_score(0-1)+ tier(safe/differentiated/innovative)**
3. **多样性规则**:3 个 selected 主推覆盖 ≥ 2 个 tier,且至少 1 个 t_score ≤ 0.50
   - 3 个全在安全层 → FAIL,退回 Phase 2 重生成
   - 提示语:「3 主推全落安全层,选题坍缩。至少 1 个主推需 T ≤ 0.50 或调低层级」

## 5. 与 Checkpoint #3 的关系

- 反坍缩校验是**闸门**(机器校验),不替代用户确认
- Checkpoint #3 的 Grill 追问新增一条:**「候选里最'反直觉'的是 X,你敢做吗?」**——把风险显性化
- 用户点名选中的可以是任何层级;选中安全层时,主报告须在「为什么选这个题」里写清「差异化不足、以保底为主」的自我认知

## 6. 边界与诚实声明

- T-Score 是启发式标尺,不是精确测量;同一题不同人打分可差 0.1。闸门只卡「全塌在安全层」这种明显坍缩,不卡数值精读
- 创新层 ≠ 更好:它是「更高风险、更高潜在贡献」。落选/被审稿人拒是常态
- 本机制只防「题目的同质化」,不防「生成过程的幻觉」(那是独立审查 review.py 的职责)

## 7. 主题对抗压测:9 类坍缩攻击清单(经管实证语境,v0.3.12)

> 用于 Step 3b 选定主题后的质检预演。理念借鉴 zhangjunhuan846-hash 的 8 类坍缩攻击(collapse-test),按经管实证语境逐条翻译,并补第 9 类「贡献类型攻击」。攻击名用中文话术,不含材料科学黑话。

### 7.1 攻击清单(每类一问 + 回应)

| # | 攻击名 | 一击致命问 | 经管实证典型坍缩态 | 对应防线 |
|---|---|---|---|---|
| 1 | 换情境攻击 | 换个样本/情境/行业/时期再跑一遍,骨架变了吗? | 把 A 股换成港股、换行业再发一遍 | 反坍缩(T-Score) |
| 2 | 换术语攻击 | 换个构念名或概念框架,实质同一件事? | ESG/环境绩效/绿色绩效换皮 | 反坍缩 |
| 3 | 识别攻击 | 处理与同期政策/选择效应/反向因果混淆,识别站得住吗? | DID 混同期改革、工具变量与遗漏变量纠缠 | 反黑箱/识别闸 |
| 4 | 已被占攻击 | 威胁文献或综述早已解答,只是不在你的文献里? | 结论可被本批外文献证伪/抢发 | 威胁文献清单 |
| 5 | 不可证伪攻击 | 假设太弹,任何结果都接得住? | 「有显著影响也有不显著的可能」 | 假设闸(Step 4) |
| 6 | 范围过宽攻击 | 宽到做不成一篇论文? | 「数字化转型对企业绩效的影响」 | 反坍缩(scope) |
| 7 | 数据质量攻击 | 测度有争议、披露有偏、样本不具代表性? | 漂绿测度口径、自愿披露样本偏差 | feasibility 闸 |
| 8 | 不可行攻击 | 识别所需数据/工具拿不到,做不了? | 需要的微观数据不在数据库/无 IV 可用 | feasibility 闸 |
| 9 | 贡献类型攻击 | 「揭示了什么」答不上,只是重复单工具主效应? | 把已知主效应塞进交互项就算新题 | 贡献类型门 |

### 7.2 生存标签(四档)

- `survives`(存活):9 类全部接得住 → 可进 Step 4 提炼假设
- `survives_if_narrowed`(需收窄):靠降级预案/聚焦子样本/换识别可化解 → 写清降级路径后放行
- `needs_pivot`(需转向):多类攻击中招,需换角度或换识别 → 把转向建议带给用户,由用户决定
- `collapses`(坍缩):核心卖点被击穿(如换情境后骨架完全暴露) → 建议换题,回到 3 主推

### 7.3 执行要求(与 check_step 3b 半强校验一致)

1. 启用「对抗压测」就必须做完整:至少攻击 6 类、每类 1 句回应、打 1 个生存标签
2. 攻击名用中文话术,禁止出现材料黑话(如 precursor / descriptor / instrument)
3. 回应须引用文献或 gap 依据;接不住的标到降级预案,不得硬撑
4. 与 Checkpoint #3 的关系:压测是「质检 + 解释」,不替代用户拍板;`needs_pivot`/`collapses` 时把建议带给用户,用户决定是否换题
